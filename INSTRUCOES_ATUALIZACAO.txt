ELLENCOCHECK 2.3 - INSTRUCOES DE ATUALIZACAO

IMPORTANTE
Enviar os arquivos ao GitHub/Render NAO atualiza o banco Supabase. A migracao SQL abaixo precisa ser executada manualmente uma vez no projeto Supabase.

1) CORRIGIR O BANCO DO HORIMETRO

- Acesse https://supabase.com/dashboard e abra o projeto usado pelo EllencoCheck.
- Entre em SQL Editor > New query.
- Abra o arquivo supabase_corrigir_v4.sql que acompanha este ZIP.
- Copie todo o conteudo para a consulta do Supabase e clique em Run.
- Aguarde a mensagem de sucesso. O script pode ser executado novamente com seguranca e nao apaga as inspeções existentes.

Correção adicional para o erro `P0001: Informe o horímetro inicial e o horímetro final`:
- O banco tinha um gatilho antigo (`definir_horimetro_checklist`) que exigia as duas leituras simultaneamente.
- O script agora substitui essa função antes de atualizar inspeções antigas.
- A leitura inicial continua obrigatória; a final pode ficar vazia ao salvar e ser registrada depois no Histórico.
- Quando a leitura final for informada, o banco valida que ela não seja menor que a inicial.

Esse reparo garante:
- checklists.horimetro_inicial: leitura antes do uso;
- checklists.horimetro_final: leitura ao encerrar o uso (pode ficar vazia inicialmente);
- checklists.horimetro_final_em: data/hora em que a leitura final foi informada;
- checklists.horas_utilizadas: diferenca entre final e inicial;
- funcao registrar_horimetro_final, usada no Historico para informar a leitura final depois;
- sincronizacao do horimetro do equipamento com a leitura final mais recente;
- recarga do cache de esquema da API do Supabase.

Se o projeto ainda nao recebeu a atualizacao v3, execute primeiro supabase_update_v3.sql para cadastrar os tipos de equipamentos, EPIs e itens especificos das maquinas. Para banco antigo, mantenha a ordem de migracoes descrita no README: v2, v3, v4 e v5. O arquivo supabase_corrigir_v4.sql e um reparo focado nos campos/funcoes do horimetro.

NAO execute supabase_schema.sql novamente em um banco em uso: ele contem dados iniciais e pode interferir em registros existentes.

2) CONFERIR O BANCO (OPCIONAL)

Depois de executar o reparo, rode esta consulta no SQL Editor:

select column_name
from information_schema.columns
where table_schema = 'public'
  and table_name = 'checklists'
  and column_name in ('horimetro_inicial', 'horimetro_final', 'horimetro_final_em', 'horas_utilizadas')
order by column_name;

Devem aparecer as quatro colunas.

Para conferir a funcao:

select to_regprocedure('public.registrar_horimetro_final(bigint,numeric)');

O resultado deve ser public.registrar_horimetro_final(bigint,numeric).

3) PUBLICAR O SITE

- Substitua os arquivos do repositorio GitHub pelos arquivos desta pasta, preservando arquivos de configuracao que ja contenham suas credenciais, principalmente supabase-config.js.
- Envie o commit para a branch conectada ao Render (normalmente main).
- Aguarde o deploy do Render terminar.
- No navegador, recarregue o site com Ctrl + F5 para evitar arquivos antigos em cache.

O arquivo supabase-config.js continua contendo a configuracao do seu projeto. Nao publique a chave service_role; no navegador deve ser usada apenas a chave publishable/anon.

4) TESTAR

- Abra uma nova inspeção e selecione um equipamento.
- Confira se o horímetro inicial aparece com a última leitura conhecida.
- Informe o horímetro final, se já estiver encerrando o uso. Ele pode ficar em branco para ser preenchido depois pelo Histórico.
- Finalize e confira se a inspeção foi salva.
- No Histórico, teste o registro posterior do horímetro final e a geração do PDF.
- Confira se EPIs e componentes específicos da máquina aparecem como itens obrigatórios.

5) MODO ESCURO

O modo escuro e os botões de alternância foram removidos. O sistema agora permanece no tema claro, independentemente da configuração de aparência do dispositivo.
